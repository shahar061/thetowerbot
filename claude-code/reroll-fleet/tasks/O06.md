# O06 — Build the fleet control room

**Status:** Not started

**Internal dependencies:** M04

**External dependencies:** none

## Outcome

Add the fleet-first dashboard: campaign health, worker rows, instance drill-down, candidate path, evidence freshness and quarantined-worker incident controls. Keep current single-worker Live, Account, Ledger and Director views as deep links.

## Acceptance gate

The UI renders stopped, running, waiting, parked, quarantined and winner states without falsely calling missing data healthy. Selecting one worker cannot issue an action to another. Any resume/retry control presents the exact target and is unavailable without an eligible recovery state.

## File map

- Inspect/modify: `web/app.py`, `web/ui/components/Sidebar.tsx`, `web/ui/lib/api.ts`, `web/ui/lib/types.ts`
- Create when absent: `web/ui/app/fleet/page.tsx`, `web/ui/app/candidates/page.tsx`, `web/ui/components/FleetTable.tsx`, `web/ui/components/InstanceInspector.tsx`
- Focused verification: `tests/test_fleet_api.py`, `web/ui/app/fleet/page.test.tsx`, `web/ui/app/candidates/page.test.tsx`

## Implementation constraints

- Show verified facts and their timestamps, not invented health/efficiency scores.
- Device preview transport is read-only. Its rate must not change capture rate or bot decision rate.
- Campaign policy edits are distinct from routine watch controls and must show their revision.

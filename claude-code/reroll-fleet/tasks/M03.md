# M03 — Add BlueStacks lifecycle adapter and recovery hand-off

**Status:** Completed

**Internal dependencies:** M01

**External dependencies:** Base B05, B06 complete

## Outcome

Introduce a BlueStacks host adapter that inventories named instances, starts/stops a designated instance, provisions a fresh instance by default, can clone a named source under a staging lease, waits for its exact device lease, and hands recovery results back to the worker supervisor without cross-instance actions.

## Acceptance gate

A simulated instance crash triggers bounded reconnect, app relaunch and host restart attempts against only its named instance. Pending transactions reconcile from a fresh observed state after recovery. A session-conflict signal quarantines the exact worker without responding to the dialog. Exhaustion quarantines that worker while another worker remains unaffected.

## File map

- Inspect/modify: `device.py`, `runner.py`, `tower_bot.py`
- Create when absent: `fleet/bluestacks.py`, `fleet/lifecycle.py`
- Focused verification: `tests/test_bluestacks_adapter.py`, `tests/test_fleet_lifecycle.py`, `tests/test_supervisor.py`

## Implementation constraints

- Start with a host-adapter abstraction; do not assume a scriptable BlueStacks Air clone/reset API exists.
- Fresh-instance provisioning is the supported default. The adapter may stage a clone only for R00/M05 qualification; O07 exposes Clone to normal campaigns only after M05 records a passed simultaneous-session qualification for this host and source version.
- Manual provisioning is a supported bounded-pool mode. Mark automatic replenish unavailable until proved on the host.
- The adapter must not kill processes merely because they occupy a TCP port.

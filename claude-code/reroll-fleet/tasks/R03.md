# R03 — Plan and collect reroll stones from available sources

**Status:** Not started

**Internal dependencies:** R02

**External dependencies:** Base B07, T01, T02, T03 complete

## Outcome

Turn observed daily/weekly, event and tournament rewards into a time-aware stone acquisition plan. Reserve stones for the next UW offer and record why the worker runs, waits, claims, buys an allowed stone pack, or skips a source.

## Acceptance gate

The planner never assumes a reward is available from historical data. It correctly distinguishes claimable, exhausted, unavailable and next-eligible sources; prevents a medal purchase that violates campaign policy; and resumes scheduled work after restart without duplicate claims.

## File map

- Inspect/modify: `missions.py`, `rewards.py`, `tournaments.py`, `currencies.py`, `planner.py`, `transactions.py`
- Create when absent: `reroll_rewards.py`
- Focused verification: `tests/test_reroll_rewards.py`, `tests/test_missions.py`, `tests/test_events_policy.py`, `tests/test_tournaments.py`

## Implementation constraints

- No real-money purchases are in scope.
- Persist eligibility timestamps and observed purchase indices; do not derive them from a fixed calendar alone.
- Compatible mission constraints are explicit run policies, not accidental side effects of farming configuration.

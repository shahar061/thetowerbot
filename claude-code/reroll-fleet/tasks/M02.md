# M02 — Create a capture-provider boundary and benchmark PNG capture

**Status:** Not started

**Internal dependencies:** M01

**External dependencies:** none

## Outcome

Decouple frame acquisition from bot decisions through a provider interface that publishes an atomic latest frame with device binding, timestamp, sequence and stale status. Preserve current ADB PNG capture as the first provider and record comparable per-worker performance metrics.

## Acceptance gate

The decision loop receives immutable current-frame snapshots and rejects a stale, wrong-device or changed-geometry frame before action. Two worker baselines report capture latency, frame age, capture/decoder failures and host-process CPU under the same policy. The dashboard preview does not increase device capture frequency when viewers connect.

## File map

- Inspect/modify: `device.py`, `frames.py`, `tower_bot.py`, `runner.py`, `config.py`, `web/app.py`
- Create when absent: `capture.py`, `capture_metrics.py`
- Focused verification: `tests/test_capture.py`, `tests/test_frames.py`, `tests/test_web_frame_stream.py`

## Implementation constraints

- Keep a single latest frame in memory; do not queue every captured frame.
- Capture and action frame sequence rules must survive worker restart.
- Make H.264 an optional provider selected only after a separate measured threshold; do not add a raw scrcpy protocol implementation in this task.

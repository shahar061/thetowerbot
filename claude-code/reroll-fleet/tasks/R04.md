# R04 — Select target UW offers and preserve candidates

**Status:** Not started

**Internal dependencies:** R03

**External dependencies:** Base B05, B07, U01 complete

## Outcome

Read all offered Ultimate Weapon choices, evaluate them against the GT+BH campaign policy, persist a selection intent, perform at most one verified pick, and classify the account as disposable, protected candidate, parked candidate or verified winner.

## Acceptance gate

Fixtures cover first and second offers containing GT, BH, both, neither, unreadable text, stale prices and restart between intent/action/verification. The worker never picks an unverified target, never treats reopening the same offer as a reroll, and preserves verified candidates before capacity is released.

## File map

- Inspect/modify: `ultimate_weapons.py`, `account_state.py`, `transactions.py`, `currencies.py`, `policy.py`
- Create when absent: `reroll_uw.py`, `candidates.py`
- Focused verification: `tests/test_reroll_uw.py`, `tests/test_ultimate_weapons.py`, `tests/test_transactions.py`

## Implementation constraints

- First-offer policy is GT preferred, otherwise BH; neither is disposable under the configured campaign policy.
- Second-offer policy selects only the missing member of the pair. A miss parks the candidate unless policy explicitly permits recycle.
- A screenshot, offer OCR and post-purchase ownership observation are separate evidence records.

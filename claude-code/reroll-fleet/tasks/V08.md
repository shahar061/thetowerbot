# V08 — Qualify a two-worker reroll campaign

**Status:** Not started

**Internal dependencies:** M02, M04, O06

**External dependencies:** Base B08, V03 complete

## Outcome

Run a bounded two-worker campaign qualification from independently provisioned disposable accounts and produce an evidence-backed report on routing, recovery, capture cost, intervention rate, candidate preservation and campaign limits.

## Acceptance gate

Injected wrong-endpoint, worker crash, stale-frame, screen-change and supervisor-restart faults cause no wrong-instance action and no duplicate spend. One worker can be quarantined while the other proceeds. All candidate/winner claims survive restart and re-observation. The report explicitly states unsupported host/account lifecycle steps.

## File map

- Inspect/modify: `fleet/supervisor.py`, `fleet/lifecycle.py`, `capture_metrics.py`, `web/app.py`
- Create when absent: `qualification/reroll_campaign.py`
- Focused verification: `tests/test_reroll_qualification.py`, `tests/test_fleet_supervisor.py`, `tests/test_capture.py`

## Implementation constraints

- Start with two workers; do not generalise capacity from unmeasured assumptions.
- H.264 may be measured in this gate, but PNG remains a valid qualified provider if it performs better on the host.
- This task certifies the campaign scope only; it does not claim full long-term game autonomy.

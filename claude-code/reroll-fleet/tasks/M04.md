# M04 — Run a restartable reroll campaign supervisor

**Status:** Not started

**Internal dependencies:** M03, R04

**External dependencies:** none

## Outcome

Coordinate isolated workers through a durable campaign database: capacity leases, campaign limits, attempt allocation, candidate retention, scheduled wake-ups, worker quarantine, winner election and hand-off to long-term mode.

## Acceptance gate

Supervisor restart preserves worker/candidate/winner state. A failed worker cannot block healthy workers. Simultaneous verified winners are both protected, while one deterministic winner is elected according to saved policy. Global attempt/time/capacity limits prevent unbounded provisioning.

## File map

- Inspect/modify: `runner.py`, `account_state.py`, `events.py`
- Create when absent: `fleet/supervisor.py`, `fleet/store.py`, `fleet/scheduler.py`, `fleet/models.py`
- Focused verification: `tests/test_fleet_supervisor.py`, `tests/test_fleet_store.py`, `tests/test_fleet_scheduler.py`

## Implementation constraints

- Workers own device actions; the supervisor may only dispatch stateful work and lifecycle commands.
- A worker must checkpoint and release its lease before an attempt can be recycled.
- Retain raw screenshots outside Git and reference them through controlled evidence paths.

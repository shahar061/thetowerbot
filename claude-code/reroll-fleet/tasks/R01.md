# R01 — Bind fresh accounts and complete the tutorial safely

**Status:** Not started

**Internal dependencies:** M01

**External dependencies:** Base B05, B08, F01 complete

## Outcome

Recognise and navigate the fresh-account tutorial while recording account/attempt binding evidence, supported tutorial milestones and every action outcome. Unknown tutorial screens enter bounded recovery rather than receiving generic taps.

## Acceptance gate

Replay fixtures cover each supported tutorial screen, confirmation, overlay and unknown branch. A disposable live account reaches the post-tutorial home state with a verified attempt binding and can restart without replaying completed tutorial actions.

## File map

- Inspect/modify: `screens.py`, `pages.py`, `tower_bot.py`, `account_state.py`
- Create when absent: `onboarding.py`
- Focused verification: `tests/test_onboarding.py`, `tests/test_screens.py`, `tests/test_replay.py`

## Implementation constraints

- Capture versioned real tutorial fixtures before enabling a handler.
- No tutorial action may be attempted from OCR text alone when anchor or screen identity is ambiguous.
- Do not automate account sign-in, cloud linking or reset until that operation has its own qualified host/account workflow.

# M05 — Qualify clone provisioning with unique Tower identities

**Status:** Completed

**Internal dependencies:** M03, R00

**External dependencies:** none

## Outcome

Qualify `tower-template` as a BlueStacks clone source only when every clone immediately receives a new in-game Tower Account ID through R00 and the resulting workers can coexist. Record the exact source instance, BlueStacks/application version, geometry, source ID, clone lineage, and simultaneous-session evidence.

## Acceptance gate

The dashboard/API can show a clone source as `pending_evidence`, `identity_reset_required`, `parallel_session_qualified`, `blocked`, or `retired`. Clone requests are refused unless the source is `parallel_session_qualified`, all evidence is fresh, and it has no protected-account match. A two-instance qualification clones the same source, runs R00 once per clone, records distinct account IDs, starts both concurrently, and restarts both. Neither worker may restore, modify, or prompt to continue the established account or the other worker. Any ambiguous account, cloud restore, `New session detected`, `Cloud Session Different Than Local Session`, changed ID, or duplicate ID makes the source `blocked` and captures an incident.

## Implementation constraints

- The established save is a protected-account deny-list entry; it cannot be selected as a template, clone source, or new-account target.
- Capture the relevant BlueStacks/Android account settings, Tower Account ID, and first-launch/session evidence as timestamped references. A missing signal is unknown, never safe.
- An unlinked source ID is not enough. A clone remains `identity_reset_required` until R00 replaces the source ID with a verified unique ID.
- A BlueStacks clone is an optimization, never the default source of identity. If qualification fails, mark cloning `unsupported_on_host` and provision fresh BlueStacks instances instead.
- A detected session-conflict dialog is a terminal quarantine signal. The bot must not choose Yes/No, force-save, link, unlink, or otherwise reconcile the account.
- Do not collect, persist, or automate credentials. A candidate or winner is never promoted to a template. `retired` templates can never be cloned again.

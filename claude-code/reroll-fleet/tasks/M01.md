# M01 — Isolate worker identity and runtime roots

**Status:** Not started

**Internal dependencies:** none

**External dependencies:** Base B01, B03 complete

## Outcome

Make one worker bind fail-closed to one exact ADB endpoint, lease and attempt identity. Give it its own database, strategy root, evidence root, checkpoints and web port. Remove the possibility that a missing requested device silently becomes another attached device.

## Acceptance gate

With two fake attached devices, a missing or duplicate endpoint prevents startup and emits an identity incident. Two valid worker configurations cannot share any writable runtime path or web port. Reusing an emulator for a new attempt creates a new immutable attempt generation.

## File map

- Inspect/modify: `device.py`, `tower_bot.py`, `runner.py`, `config.py`
- Create when absent: `fleet/identity.py`, `fleet/runtime.py`
- Focused verification: `tests/test_fleet_identity.py`, `tests/test_device.py`, `tests/test_runner.py`

## Implementation constraints

- Replace fallback-to-first-attached-device behaviour with an explicit error in fleet mode.
- Treat ADB serial aliases as transport aliases, never account identity.
- Accept and persist an attempt binding only after it is supplied with observed identity evidence; retain the evidence reference and timestamp. R00 owns navigating Settings → Account and reading the Tower Account ID; M01 must not depend on that reader being implemented.
- Keep the existing single-worker CLI compatible while adding explicit worker-root configuration.

# O07 — Add BlueStacks template cloning to the Fleet dashboard

**Status:** Not started

**Internal dependencies:** M03, M05

**External dependencies:** none

## Outcome

Add a Fleet dashboard provisioning surface that defaults to named fresh BlueStacks instances and, only where qualified, offers clone requests from approved templates. It shows account-safety and simultaneous-session evidence, fulfils clone requests through BlueStacks Multi-instance Manager, then registers new instances and waits for exact endpoint/lease validation before they become runnable workers.

## Acceptance gate

The UI exposes Fresh instance for any eligible capacity, and exposes Clone only for one selected source that is `parallel_session_qualified` after R00 replaced the source account identity on two concurrent clones. It displays its evidence timestamp, target names, requested count, and resulting state. A request creates uniquely named instances such as `tower-reroll-001` and records every host step. It blocks for a stale/unknown/blocked source, session-conflict evidence, protected-account match, duplicate name, capacity limit, or an unobserved ADB endpoint. A failed or interrupted Multi-instance Manager operation creates no runnable worker and offers only retry or quarantine against the exact request.

## Implementation constraints

- Implement the BlueStacks Multi-instance Manager as a qualified host adapter. Do not pretend there is a stable BlueStacks clone API until the installed host proves one; a UI-driven adapter may be the implementation.
- The dashboard action is a provisioning request, not immediate proof of a safe worker. It remains `creating` until the manager reports completion, M01 identity checks pass, and the worker has passed its first-launch identity check.
- Surface `session_conflict` as a blocking incident with the exact screenshot and source/worker IDs. The dashboard must never offer an automatic Yes/No response.
- Require an explicit configured fleet capacity and instance-name prefix. Never auto-clone from an arbitrary row, candidate, winner, or protected account.
- Do not automate account sign-in, cloud linking, account unlinking, or credential entry. Account-safety failures must be quarantined for operator review.
- The UI must show a direct route to the evidence and the BlueStacks manager result for every request.

# R00 — Create and verify a unique Tower account per instance

**Status:** Completed

**Internal dependencies:** M01, M03

**External dependencies:** Base B05, B08 complete

## Outcome

Automate the in-game identity reset required after provisioning an instance: open **Settings → Account → New Account**, then read the resulting Tower Account ID and bind it to the exact instance and attempt. Each runnable worker starts with a unique, independently verified Tower account identity, even when its BlueStacks instance was cloned from a shared install source.

## Acceptance gate

Replay fixtures cover Settings, Account, Account-ID reader, New Account control, its confirmation/transition, loading state, and every unknown/blocked branch. Given two cloned disposable instances that initially expose the same source ID, each runs the New Account workflow exactly once and produces a non-empty ID different from its prior ID, the other worker’s ID, and every protected/active account ID. The IDs, screenshots, timestamps and source-instance lineage persist durably. Both workers can then open in parallel and restart without `New session detected`, `Cloud Session Different Than Local Session`, an account-restore prompt, or a changed ID. Any mismatch or dialog quarantines the exact worker without choosing an answer.

## Implementation constraints

- Treat the Tower Account ID shown under Settings → Account as the primary game identity. It is distinct from an ADB serial, BlueStacks instance name, and email address.
- Require an explicit `new_account` transaction intent, exact pre-state ID, exact instance lease, and one post-action ID observation. Never repeat the action after restart solely because its result is uncertain.
- Reject a blank, unreadable, unchanged, duplicated, protected, or stale ID. Record it as `identity_conflict` and quarantine the worker.
- The bot may use only the in-game **New Account** action. It must never select Change Account, Force Cloud Save, email, Change Email, Change Password, a system Google account, or enter credentials.
- This is an account-creation action within a disposable campaign. It is allowed only by campaign policy and only before the attempt enters tutorial/progression. A candidate or winner is never reset.
